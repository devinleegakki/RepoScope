# 演示执行卡

两条路径都验证过可跑。上台按这个顺序，不要反。

---

## 一、两条命令

| 场景 | 双击 | 或命令行 |
|---|---|---|
| **真实数据**（自己仓库） | `run_real.bat` | `python run_gui.py --path .` |
| **演示数据**（160 次提交） | `run_gui.bat` | `python run_gui.py --demo` |
| 手动挑仓库 | — | `python run_gui.py` |

VS Code 里按 `F5`，选「打开界面（真实仓库 RepoScope）」或「打开界面（演示数据）」，效果一样。

`--demo` 和 `--path` 互斥，同时给会直接报错。

## 三、真实模式下哪几页是空的（务必先知道）

真实仓库只有 10 次提交、全在同一天，所以：

| 页面 | 真实模式下 | 现场怎么处理 |
|---|---|---|
| 总览仪表板 | 正常，5 张卡都有数 | **主战场，停在这里讲** |
| 反模式中心 | 1 条 high：单一作者依赖 90%（阈值 70%） | **第二战场，这是真实发现** |
| 提交趋势 | 折线只有 1 个点、热力图只有一列 | 一句话带过，或直接跳过 |
| 作者贡献 | 2 个人，条形图能看但单薄 | 可看 |
| 数据分析 | **三个榜全空**（热点 0 / 大文件 0 / 陈旧 0） | 跳过，别说"这里应该有数据" |
| 多仓库对比 | 空队列 | 跳过 |

热力图只有一列不是 bug——10 次提交都在同一天。如果被问，就说"仓库历史集中在一两次导入，这也是工具想暴露的问题之一"。

## 四、推荐演示顺序（15 分钟版）

**第 1 步｜先跑真实（`run_real.bat`），3 分钟**

> "这是我们自己的仓库。工具读完 git 历史，10 次提交、2 位作者、42 个文件，健康度 88。"
> "反模式中心抓到一条 high：**90% 的提交来自同一个人，阈值是 70%**。这不是我们编的，是它从 `git log` 算出来的。"

这一步的作用是**建立可信度**。观众亲眼看着窗口打开、进度条动、1.2 秒出结果，全程没联网。

**第 2 步｜再切演示数据（`run_gui.bat`），7 分钟**

切换时说这一句，很重要：

> "真实仓库只有 10 次提交，图表看不出效果。所以另外准备了一份 160 次提交、102 天的数据集，用来展示界面在**数据充足时**的样子。"

然后依次点：总览 → 提交趋势（日/周/月切换，热力图铺满）→ 作者贡献（4 人条形图）→ 数据分析（三个榜都有内容）→ 报告区（Markdown 预览 + 导出）。

**第 3 步｜讲架构（`gui/` 目录），5 分钟**

九页 = 九个文件，加三个公共层（`contract` 字段契约 / `widgets` 复用控件 / `plotting` 图表封装）。分析在 `QThread` 子线程跑，主线程只收信号——所以切页不卡、分析不白屏。

## 五、三个几乎一定会被问的问题

**"这些数据是真的吗？"**
真实那一步是真的（`git log` 读出来的），演示数据那一步界面上明写「演示数据集 · 160 次提交 · 4 位作者」，状态栏也写「演示数据模式」。**主动说明，不要等他问**——主动说是诚实，被问出来是心虚。

**"为什么健康度是 88 不是 100？"**
扣分项在反模式：单一作者依赖是 high 级别，扣得最多。健康度 = 100 − 各条规则的加权扣分，权重写在配置里，可以在「分析配置」页改阈值再跑一次，分数会变。

**"不联网也能跑？"**
能。开飞行模式演示都行。唯一的外部依赖是 `rich`（终端表格），GUI 只用 PySide6，git 数据靠本地 `git` 命令。
