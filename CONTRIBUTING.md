# Contributing

1. Create a focused feature branch from `main`.
2. Keep public behavior and shared model fields backward compatible.
3. Add or update tests for rules, services, reports, CLI behavior, or GUI behavior.
4. Update the relevant documentation and inline docstrings.
5. Run compile and test checks locally before opening a pull request.
6. Describe user-visible changes, validation, and known limitations in the pull request.

Use clear commits such as `feat:`, `fix:`, `docs:`, `test:`, or `refactor:`. Do not commit generated reports, caches, secrets, or screenshots unless they are intentional artifacts.
